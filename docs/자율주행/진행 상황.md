  - 가지 승격: **보드 작업으로만**. 모델은 작업 가지에만 커밋하고, 다른 가지(live·master) 맞추기는 프로젝트 규칙이 시켜도 보류해 끝난 뒤 보드가 바뀐 줄을 보여 사람이 누를 때 한다. 엔진은 출발·끝의 가지 머리를 `run.json` 의 `branches` 에 남긴다. 계기: 실제 프로젝트의 두 번째 실행에서 모의 서버 저장소의 단위 둘이 프롬프트대로(프로젝트 규칙의 예외) live·master 를 dev 로 맞췄다.

  - 함께 작업: 처음엔 추천(알림만) 대신 **따로 작업 트리**를 골랐고, 저장소 묶음(중심 저장소가 다른 저장소를 상대 경로로 가리키는 프로젝트)의 대가(형제 저장소 상대 경로 `../<다른 저장소>`, 프로젝트 규칙의 dev 가지, git 이 무시하는 `data/`·`.env`, 첫 빌드, 합칠 때 충돌)를 들은 뒤 **묶음은 알림만, 단일 저장소는 따로 작업 트리가 되는지 확인해서 되면 그렇게**로 정했다. 보드가 출발 준비 때 기계로 가려 출발 확인에 "어디서"와 이유를 보인다. 따로 작업 트리는 `~/.claude-board/worktrees/<실행 id>/<저장소>/`, 가지 `autopilot/<실행 id>`, 끝나면 보드의 합치기(앞으로 감기, 아니면 병합 커밋, 충돌이면 사람에게)·버리기. 지금 돌리는 실제 프로젝트는 묶음이라 원래 작업 트리 + 알림이다. 같은 세션의 장난감 실측(서브에이전트, haiku 0.03 USD): 원래 `.git` 의 넷(`objects`·`refs/heads/autopilot`·`logs/refs/heads/autopilot`·`worktrees/<이름>`)과 `packed-refs.lock` 만 열면 작업 트리에서 커밋이 되고, 기존 가지 ref·`packed-refs` 쓰기 금지로 main·live 를 옮기거나 지우는 것이 일반·압축 상태 모두 막힌다(압축된 가지는 무엇이든 못 지움). 좁은 설정은 `sandbox-exec` 로 쟀으므로 실제 자리에서 Claude Code 로 다시 잰다. 그래서 원래 작업 트리 모드도 일할 가지(`work_branches`) 밖의 기존 가지를 쓰기 금지하기로 했다(설계 판단). 장난감과 기록은 이 세션 scratchpad `wt-test/`(지워지는 자리).

### 실측 (claude 2.1.304, macOS 26)

- **`-p` stream-json 에서 SIGINT**: 0.6초 만에 종료 코드 0 으로 끝나고, 마지막에 result `subtype "error_during_execution"`, `is_error` true, `terminal_reason "aborted_tools"`, `stop_reason "tool_use"` 를 낸다(그 앞에 `task_notification` status stopped, 도구 결과는 "The user doesn't want to proceed…"). 돌던 Bash 도구의 zsh·python(따로 process group)도 함께 끝났다. 엔진 시험에서도 일시정지·상한·중단 모두 1~2초 안에 멈췄다.
- **입력 닫기**: result 뒤 입력(stdin)을 닫으면 0.56초 만에 코드 0 으로 끝난다(옛 엔진 주석 "스스로 끝나지 않는다"(2026-10-14)는 이 판에서 맞지 않음). 한 프로세스에 메시지를 이어 보내면 result 가 하나씩 더 온다.
- **rate_limit_event**: `{"type":"rate_limit_event","rate_limit_info":{"status","resetsAt","rateLimitType","overageStatus","overageDisabledReason","isUsingOverage","unifiedWindows":{"five_hour":{"utilization","resetsAt"},"seven_day":{"utilization","resetsAt"}}},"uuid","session_id"}`. utilization 은 0~1(0.01 단위), resetsAt 은 유닉스 초. 이번 시험에서는 claude 프로세스마다 첫 요청 때 한 번 왔다(10번, 모두 allowed·five_hour). 옛 기록(1,320개): `allowed`·`allowed_warning`(이때 `utilization`·`surpassedThreshold`·`overageEnabled` 가 더 붙고 `unifiedWindows` 에 `seven_day_overage_included` 가 오기도 함)·`rejected` 1번(seven_day, utilization 1). 거절 때 assistant 사건은 `model "<synthetic>"`, `error "rate_limit"`, `api_error_status 429`, `api_error "usage_limit_reached"`, `api_error_params.rate_limit_info`, 글 "You've hit your weekly limit · resets 4pm (Asia/Seoul)", 이어서 result `subtype "success"`·`is_error` true·`api_error_status` 429·`terminal_reason "api_error"`.
- **`--resume` 직후 빈 result**: 이번 판에서는 나오지 않았다(SIGINT 뒤 이어 열기 1번, 엔진 시험의 이어 열기 5번). 옛 기록에는 이어 연 직후(init 다음)와 세션 중간에 `num_turns 0`·`result ""`·`is_error false` 가 있었다 — 규칙은 남긴다.
- **launchd 가 자식을 함께 끝내는지**: 작업(엔진)이 죽으면 launchd 가 그 process group 을 끝낸다. 따로 만든 LaunchAgent 시험에서 같은 group 의 `sleep` 은 끝나고 `setpgrp` 한 프로세스는 살아남았다. 엔진 시험에서 엔진과 같은 group 의 claude 는 0.7~2.7초 뒤에 끝났다(스스로 정리하며 도구 명령도 끝냄). 첫 시험에서는 3.5초 만에 엔진이 다시 떠 아직 살아 있던 claude 를 새 엔진이 끝냈다 — 그래서 새 엔진은 늘 남은 claude·group 을 먼저 치운다.
- **비용**: result 의 `total_cost_usd` 는 프로세스 안에서 쌓이고 새 프로세스(`--resume` 포함)에서는 0 부터다(0.00105 → 이어 연 프로세스 0.00145).
- **권한**: `--permission-mode dontAsk --permission-prompts none` 에서 허용 목록 밖과 거부 목록은 묻지 않고 거부되고 result `permission_denials` 에 `{tool_name, tool_use_id, tool_input}` 으로 남는다. `Edit(**/CLAUDE.md)`·`Edit(.claude/**)` 는 Write·Edit 도구 모두 막았다. `Bash(git push *)` 는 `git push origin …` 을 막았지만 `git -C . push …` 는 통과했다 → 환경 변수 git 설정(`url.autopilot-push-blocked:.pushInsteadOf` 빈 값)으로 push 만 막힘을 확인(fetch 는 됨). `--disallowedTools` 는 값을 여러 개 받아 뒤에 오는 질문 글까지 삼킨다(stream 입력이라 엔진에는 상관없음).
- **도구 이름**: init 의 tools 에는 `Task` 로 나오지만 실제 tool_use 이름은 `Agent` 였다. 허용 목록의 `Task` 로 허용됐다.
- **로그인 셸**: `zsh -l -c` 만으로는 `~/.local/bin`(claude)이 PATH 에 없다(이 Mac 은 .zshrc 에서 붙임). `-i -l` 은 찾지만 `alias claude=…` 가 함께 오고 powerlevel10k 의 gitstatus 안내가 출력된다. launchd 작업의 환경은 `PATH=~/.cargo/bin:/usr/bin:/bin:/usr/sbin:/sbin`, `SHELL`·`HOME`·`USER`·`LOGNAME`·`TMPDIR` 있음, `LANG` 없음.

### 설계·지시와 다르게 한 곳

- **claude 띄우기**: 지시는 `$SHELL -l -c 'exec claude "$@"'` 꼴이었는데, 위 실측대로 `-l` 만으로는 claude 를 못 찾고, 매번 `-i` 로 띄우면 .zshrc 출력이 stream 에 섞이고 별칭이 따라온다. 그래서 엔진이 뜰 때 `$SHELL -i -l -c 'env -0'` 으로 환경을 한 번 읽어(보드 3.0 의 LoginEnvironment 와 같은 방식) claude 를 그 환경으로 바로 띄우고, 판정 명령은 그 환경에서 `$SHELL -l -c` 로 돌린다.
- **엔진 자리**: 앱 `Contents/MacOS/claude-autopilot`. `user-setup.sh` 가 notifier 파일을 이름으로 골라 옮기므로 `~/.claude/notifier` 에 두면 pkg 설치 길이 갈라진다. 출발 때 실행 폴더에 고정하므로 보드가 앱 안의 것을 부르면 된다.
- **한 턴 = 프로세스 하나**: 판정 실패 뒤 다시 하기도 `--resume` 으로 새 프로세스를 띄운다(일시정지·한도·다시 뜨기와 같은 길).
- **빈 result**: "이어 연 직후"만이 아니라 언제 와도 끝으로 세지 않는다.
- **git push**: 거부 규칙 + 환경 변수 git 설정 둘 다.
- **process group**: claude 는 엔진과 같은 group(launchd 가 함께 끝냄), 판정 명령은 따로 group(통째로 끝냄). 도구 명령 group 은 엔진이 적어 두었다가 치운다.
- `review` 칸은 읽기만 한다(리뷰 세션은 3단계 이후). `takeover`·`giveback`·`restart_from_intake` 는 받으면 "아직 엔진이 하지 못하는 요청"으로 기록하고 넘긴다.
- 시험용 `run.json` 칸 `claude_args`·`claude_path` 를 더했다(설계 4장).

- **저장소 하네스와 지시가 부딪힐 때**: 쓰는 법 여섯을 따른 지시(1,154자)와 따르지 않은 지시("절대 사람에게 묻지 마라. 반드시 끝까지 하라.")를 같은 단위로 견줬다. 단위 둘은 운영 값 둘이 정해지지 않은 설정 파일(사람 몫)과 제목 후보 둘 가운데 고르는 절(사람 몫 아님). haiku 로 두 글 각각 두 번씩(8단위), 애매해서 sonnet 으로 따르지 않은 지시 한 번(2단위). 열 단위 모두 묻지 않고 끝났다. 운영 값은 비우고 `next_start` 로 보류(outcome `parked` 또는 `done`), 제목은 하나를 골라 `decisions_applied` 에 적었다. 다른 것은 근거 글뿐: 따른 지시는 "출발 카드에 답이 없어"·"자율주행 지시의 사람 몫 기준", 따르지 않은 지시는 저장소 CLAUDE.md 의 확인 규칙을 근거로 적었다. sonnet 은 "프로젝트 지침은 모호하면 사람에게 확인받으라고 하지만, 이 세션은 묻지 않는 모드라"고 적었다. 이 크기에서는 시스템 프롬프트의 공통 규칙이 이미 CLAUDE.md 를 이긴다. 쓰는 법은 그대로 두고 확인 지점이 많은 실제 하네스에서 다시 견준다(설계 7장).
- **묻기 도구**: `-p` 모드의 init 도구 목록에 `AskUserQuestion` 이 없다. 그래서 "묻기 도구가 거부된 뒤"는 일어나지 않고, 묻는 길은 턴 끝의 글뿐이다(시험에서 0번).

- **SQLite**: 마지막 연결을 닫지 않고 `exit` 하면 WAL 이 접히지 않는다(옮겨 담기 끝에 닫게 고침). macOS 의 SQLite 는 닫은 뒤에도 빈 `-wal`·`-shm` 을 남긴다.
- **빈 `.cc-writes`**: 모든 시험 실행에서 claude 가 Write·Edit 을 쓴 저장소 맨 위에 만들었다(엔진이 끝에 치움).

## 엔진 고침 2차 (2026-10-22, 가지 `autopilot-stage2` 의 daa4851 위, 사용자 결정으로 커밋)

다음 작업 지시 3 의 ⑤ 가지·⑥ 판정 미리 돌리기·⑦ Jira 가지 구조. 따로 작업 트리(3-2)는 다음 차례라 `worktree.mode` 는 늘 `in_place` 다. 같은 시간에 다른 세션이 첫 실제 프로젝트 쪽(지시 옮기기 ④, 가져오기 스크립트)을 고쳤고, 이 차례는 엔진·공개 문서만 고쳤다.

바꾼 것
- 엔진, 가지: `start` 가 단위 작업 폴더·쓰기 범위가 든 git 저장소마다 고른 출발 가지(`run.json` 의 새 칸 `base_branch`, 가지 이름 하나 또는 `{저장소 경로: 가지}`, 없으면 지금 걸린 가지) 머리에서 `autopilot/<실행 id>` 를 만들어 원래 작업 트리를 바꾼다(`git switch -c`). 하네스 사본은 바꾼 뒤에 뜬다. 저장소 하나라도 바꾸지 못하면(커밋 안 한 변경이 부딪힘 등) 바꾼 저장소를 되돌리고 가지를 지운 뒤 출발하지 않는다. LaunchAgent 쓰기·올리기가 실패해도 되돌린다. `run.json` 의 `branches`(저장소마다 `base`·`work`·`original`·`restored` 와 엔진 상태 `on`·`made`·`dirty_start`·`git_dir`·`common_dir`, 출발·끝 가지 머리 `start`·`end`, `moved`·`created`)와 `worktree`(`mode: in_place`, 이유). 출발 전 `status` 에 저장소마다 출발 가지·지금 가지·커밋 안 한 변경 경고.
- 엔진, 끝 순서: 하네스 끝 검사·빈 자리 치우기 → 가지 끝 머리(`moved`·`created`) → 기록 저장소 → 출발 때 가지로 되돌리기 → 한 번 더 기록 → `wrapped`. 되돌리기는 엔진이 마지막에 걸어 둔 가지에 그대로 있고 `git status --porcelain` 이 출발 때와 같을 때만 한다. 이미 원래 가지면 `restored: true` 로만 적고, 정리 중 끊겨 다시 돌면 한 단계는 건너뛴다.
- 엔진, 모델 쪽 가지 보호: 단위마다 샌드박스 `denyWrite` 와 파일 도구 거부 규칙에 출발 때 있던 가지와 엔진이 만든 가지 가운데 지금 작업 가지를 뺀 ref 파일과 그 `.lock`, `HEAD`, `packed-refs`, `config`. Jira 스토리 가지 꼴의 앞 폴더(예 `features/parent`)는 통째로. `HEAD.lock`·`packed-refs.lock` 은 열어 둔다(아래 실측).
- 엔진, 공통 규칙: "커밋은 엔진이 걸어 둔 지금 작업 가지에만, 한 일은 턴을 끝내기 전에 커밋. 가지를 바꾸거나 다른 가지를 옮기거나 지우거나 맞추지 않는다(이유: 사람이 바뀐 줄을 보고 보드에서 하는 일, 샌드박스도 막음). 프로젝트 규칙이 시키면 지금 작업 가지에 커밋하고 맞추기는 `next_start` 에 무엇을 어느 가지로". 첫 입력에 저장소마다 작업 가지, Jira 작업이면 스토리 가지와 "엔진이 합친다".
- 엔진, `finish <실행 폴더> merge --into <가지> [--story <키>]`·`promote <가지> --into <가지>`·`discard [--story <키>]`: 사람이 명령으로만 부르고 엔진이 스스로 부르는 길은 없다. 끝나고 정리를 마친 실행만 받는다. 프로젝트 설정 `projects/<프로젝트>.json` 의 `promotion` 차례(`after`)를 지키고, 차례가 없으면 `merge` 는 차례 없이 되고 `promote` 는 거부한다. 받는 가지가 그대로면 앞으로 감기, 앞서 나갔으면 `merge-tree --write-tree` + `commit-tree` 병합 커밋(체크아웃 없이), 충돌이면 아무것도 하지 않는다. 받는 가지가 어느 작업 트리에 걸려 있으면 그 작업 트리에 추적 파일 변경이 없을 때만 그 자리에서 `merge --ff-only`, 아니면 거부. 저장소 묶음은 모든 저장소를 먼저 계획해 하나라도 충돌·거부면 아무것도 바꾸지 않는다. `discard` 는 어느 단계도 합치기 전에만, 가지가 작업 트리에 걸려 있으면 거부, 스토리 단위면 스토리 가지와 그 작업 가지를 함께 지운다. 한 일은 `branches.promoted`·`discarded` 와 기록 저장소 `runs.branches`.
- 엔진, `prerun <실행 폴더> [--dev]`: 출발 전에만. 고정 단계가 없고 `prerun` 이 참(기본)인 단위의 판정을 엔진과 같은 환경(로그인 셸, 고른 환경 변수, 밖에서 도는 git 보호, `$CLAUDE_BOARD_EVIDENCE_DIR` = `prerun/<n>/`)으로 한 번씩, 판정 시간 상한 안에서 돌린다. 시험 환경 확인(`precheck`)이 있으면 먼저 돌려 실패하면 판정을 돌리지 않는다. 결과 `prerun.json`(`where`·`units`·`already_passing`·`cards`): 일하기 전부터 통과한 단위는 출발 카드 감(빼기(추천)·판정 고치기·그대로). 원래 작업 트리라 지금 자리에서 돌고, 지금 가지가 출발 가지와 다르면 알림만 한다(작업 트리를 바꾸지 않음). 출발 전 `status` 에 마지막 결과 한 줄. 가져오기 스크립트에서 부르는 일은 그 프로젝트 몫.
- 엔진, Jira 가지 구조: 대기열 단위 칸 `story`(스토리 키)·`branch`(작업 가지, 없으면 `tickets` 첫 키로 꼴을 채움)와 새 칸 `depends`(기대는 앞 단위 id 배열). 가지 이름 꼴은 프로젝트 설정 `tickets.branch_names`(없으면 `features/parent/{story}`·`features/{task}`), 합치는 꼴 `tickets.merge`(기본 병합 커밋, `ff`). 스토리·작업 가지는 이 실행이 만들 가지여야 하고 이미 있으면 출발하지 않는다. 단위를 시작할 때 스토리 가지(없으면 출발 가지 머리에서)와 작업 가지(스토리 가지 머리에서)를 만들어 그 저장소를 작업 가지로 바꾸고, 다른 저장소와 Jira 가 아닌 단위는 `autopilot/<실행 id>` 에 둔다. 판정을 통과하면 체크아웃 없이 스토리 머리가 작업 머리의 조상인지 보고(`merge-base --is-ancestor`), 그러면 작업 머리의 tree 로 병합 커밋(부모 스토리 머리 + 작업 머리)을 `commit-tree` 로 만들어 스토리 ref 만 old 값을 준 `update-ref` 로 올린다. 작업 머리 = 스토리 머리면 "합칠 커밋 없음", 조상이 아니면 합치지 않고 사람 몫으로 남긴다. 미통과·상한·중단 작업은 가지만 남기고, 그 작업에 기대는 뒤 작업은 새 상태 `skipped`(건너뜀)로 넘긴다. 앞 작업이 커밋하지 않고 남긴 변경은 다음 작업 가지로 바꾸기 전에 그 작업 가지(엔진이 만든 가지)에 엔진이 커밋해 둔다. `branches.stories`(`repo`·`branch`·`base`·`head`·`merged`·`unmerged`), 단위 `engine.json` 의 `merge`·`branch`, 기록 저장소 `units` 의 `story_key`·`task_key`·`branch`·`merged`. Jira 요청은 0 이다.

실제 엔진 실행에서도 같았다: Jira 시험 첫 단위가 엔진이 건 샌드박스 안에서 스토리 가지 `update-ref`·지우기·새 스토리 꼴·스토리 `.lock`·live·main·자율주행 가지 `update-ref`·`switch main`·`pack-refs` 를 돌려 모두 막혔고, 새 작업 꼴 가지만 만들어졌다(그 가지는 바로 지움).

### 설계 판단 (설계.md 4장 "엔진 고침 2차 판단")

- `HEAD.lock`·`packed-refs.lock` 은 열어 둔다(실측). 그래서 모델이 남긴 `HEAD.lock` 은 그 뒤 커밋과 엔진의 가지 바꾸기를 막을 수 있다(엔진은 지우지 않고 "되돌리지 못했습니다"로 알림).
- 되돌리기의 "깨끗함"은 `git status --porcelain`(추적 안 하는 파일 포함, 무시 파일 제외)이 출발 때와 같음이다. 보통은 비어 있음이고, 사람이 출발 전부터 고쳐 둔 파일이 그대로면 함께 원래 가지로 돌아간다.
- Jira 실행도 저장소마다 `autopilot/<실행 id>` 를 만든다(Jira 아닌 단위와 다른 저장소가 거기서 돈다). Jira 단위만 있으면 그 가지는 출발 가지와 같은 자리에 남고 `finish merge` 는 "그대로"다.
- 앞 작업이 커밋하지 않고 남긴 변경은 다음 작업 가지로 바꾸기 전에 그 작업 가지에 엔진이 커밋해 둔다(다음 티켓 가지에 섞이지 않고, 미통과 작업의 일이 그 가지에 남는다). 출발 때부터 작업 트리가 더러웠으면 커밋하지 않고 그 단위를 건너뛴다.
- 실행 중에 사람이 원래 작업 트리의 가지를 바꾸면(엔진이 걸어 둔 가지와 다르면) 그 뒤 단위는 모두 시작 전 가지 확인에서 건너뛴다. 모델이 사람의 가지에서 일하는 길을 막는 쪽을 골랐다(그 가지는 어차피 쓰기 금지라 커밋이 실패한다).
- 건너뜀은 새 단위 상태 `skipped` 다. 대기열 항목은 끝남이 되지 않아 다음 출발에서 다시 고른다. 기대는 단위는 `depends` 로만 정한다(대기열 순서로 짐작하지 않음).
- `finish` 의 `merge` 는 프로젝트 설정에 승격 차례가 없으면 차례 없이 되고, `promote`(기존 가지끼리)는 차례가 있어야 한다. 받는 가지가 걸린 작업 트리는 추적 파일 변경만 본다(추적 안 하는 파일은 앞으로 감기를 막지 않는다).
- `prerun` 은 지금 자리에서 돌고 출발 가지와 다르면 알림만 한다(판정이 git 이 무시하는 파일에 기대면 다른 작업 트리에서는 결과가 달라서, 그리고 사람의 작업 트리를 바꾸지 않으려고). 카드 감의 꼴은 `{id, unit, kind: "prerun", title, why, options[{key, label}], recommended}`.
- 엔진이 바꾸는 git(가지 만들기·바꾸기·병합 커밋·ref 올리기)은 밖에서 도는 git 보호(시스템·전역 설정 끔, fsmonitor·hooks 끔)를 그대로 쓰고, 커밋 신원만 저장소 설정의 `user.name`·`user.email`(없으면 엔진 이름)을 명령줄로 붙인다.

### 남은 한계

- 따로 작업 트리(3-2)가 없어 단일 저장소도 원래 작업 트리에서 돈다. 실행 중 그 작업 트리의 사람 작업은 막지 않는다(사람이 가지를 바꾸면 그 뒤 단위는 Jira 든 아니든 모두 건너뛰고, 끝에 되돌리지 않는다).
- 엔진의 가지 바꾸기는 전역 git 설정을 읽지 않으므로 사용자 전역 설정의 LFS 필터·`core.autocrlf` 등이 적용되지 않는다(커밋이 다른 자리로 바꿀 때만 영향).
- 앞 작업이 남긴 변경을 엔진이 그 작업 가지에 커밋할 때 `git add -A` 라, 무시 목록에 없는 추적 안 하는 파일(모델이 두고 간 내려받은 파일·설정 등)도 그 가지에 들어간다. Jira 작업 가지에 남긴 커밋은 스토리로 합쳐지지 않지만(합치기는 판정 통과 때 한 번), Jira 아닌 단위가 자율주행 가지에 남긴 것은 그 가지를 `finish merge` 로 dev 에 합칠 때 함께 간다(바뀐 줄을 보고 합친다).
- 모델은 새 가지를 만들 수 있다(`created` 에 `by: other` 로 보고, 막지 않음). 가지가 아주 많은 저장소는 거부 목록이 길어진다(가지마다 두 줄).
- 저장소 묶음의 하네스 지문은 단위 작업 폴더의 저장소만 잰다(쓰기 범위로만 쓰는 저장소는 1차와 같이 재지 않음, 쓰기 금지는 함).
- 옛 판의 하네스 읽기는 이 macOS 에서 FIFO·장치 파일 링크를 만나도 멈추지는 않았다(Foundation 이 읽지 못하고 건너뜀). 대신 그런 파일은 끝 검사에 보이지 않았고, 큰 파일은 통째로 읽었다. 고친 판은 보이게 하고 크기를 막는다.
- `finish` 는 아직 보드 화면이 없어 사람이 명령으로 부른다(2단계 승격 화면이 같은 명령을 부른다). 스토리가 live 에 합쳐진 뒤의 "합친 가지 지우기"는 2단계.

정리: 시험 빌드 뿌리의 `zz-fix2-*` 실행 폴더·엔진 전용 폴더·프로젝트 설정, 기록 저장소의 그 행, 실측용 `runs/zz-fix2-measure/`, 시험 세션 기록을 지웠다(아래 "시험 방법"의 끝 확인). LaunchAgent·남은 엔진 0.

비용: 시험 모델 비용 합 약 0.09 USD(haiku 엔진 실행 0.062, 쓰기 범위 실측 세션 넷 0.026. 가짜 claude 의 값은 실제 비용 아님).

### 쓰기 범위 실측 (claude 2.1.307, git 2.50.1, 실제 Claude Code 샌드박스 `--settings`, haiku. 실측 자리 `~/workspace/zz-autopilot-wt-measure/`, tmp 밖)

- **공통 `.git` 은 자동 쓰기 허용**: 작업 트리(cwd)가 git 작업 트리면 Claude Code 샌드박스가 그 저장소의 공통 `.git` 을 통째로 쓰기 허용한다(`allowWrite` 에 넣지 않은 `refs/heads`·`objects/info` 까지 [W]). 그래서 따로 작업 트리 모드도 원래 작업 트리 모드와 같은 가지 거부 목록이 필요하다(2차의 첫 실측에서 `update-ref dev`·`HEAD` 가 통과한 것은 거부 목록이 불완전했을 때의 결과이지 샌드박스 누수가 아니다).
- **거부 목록으로 다 막힌다**(전체 거부 목록으로 다시 재어 결정): 작업 가지 커밋·새 `autopilot/*` 가지·`.gitattributes` 쓰기는 되고, 다른 가지(dev·live·master 는 압축, main 은 걸림) 옮기기·지우기, 공통 `HEAD`·`packed-refs`·`config`, 보안(공통 `.git` 이름 바꾸기, 작업 트리 `.git` 파일, `commondir`·`gitdir`, `objects/info/alternates`, config filter 심기, replace ref, shallow)이 모두 막혔다. 태그 만들기만 되고(그래서 `endBranches` 가 보고), `git worktree remove`(--force 없이)는 무시 파일(.env·data)만 있을 때 작업 트리를 지우고 원본은 보존했다.
- **`.git` 바꿔치기는 두 모드 다 샌드박스가 이미 막는다**(`mv .git .git-x`·`.git` 파일 쓰기·commondir·gitdir·config filter 모두 Operation not permitted). 왜 막히는지는 Claude Code 쪽이라 확인하지 않았고, 규칙이 바뀌어도 엔진의 `gitDirOK`(inode·장치·절대 경로 비교)와 git 강화 env 가 받친다.
- 고른 길: 작업 트리 모드 쓰기 허용은 작업 트리뿐(공통 `.git` 은 Claude Code 가 자동 허용), 거부는 원래 모드와 같은 가지 보호 + 공통 `.git` 설정 자리 + 보안(replace·shallow·작업 트리 `.git`·commondir·gitdir).

### 설계 판단 (설계.md 4장 "엔진 고침 셋째 판단")

- 작업 트리 모드 쓰기 허용은 작업 트리뿐이고 공통 `.git` 보호는 거부 목록으로 한다(공통 `.git` 이 Claude Code 자동 허용이라, 실측). 그래서 두 모드의 가지 보호가 거의 같고 작업 트리 쪽만 `.git` 파일·commondir·gitdir 을 더 막는다.
- ④ precheck 실패 시 작업 트리를 지우고 원래 작업 트리로 떨어진다(fallback). precheck 가 없는 단위는 ①②③ 만으로 작업 트리가 된다.
- 함께 둘 파일은 복사가 기본, `{path, link}` 로 읽기 전용 바로가기(원본을 모델이 못 고침). 자리는 세트 `worktree_files.json` 또는 run.json `worktree_files`. 복사가 기본인 것은 2026-10-22 사용자 결정으로 정했다(처음엔 뒤집을 수 있는 설계 판단). 비밀이 든 `.env` 는 작업 트리(모델 쓰기 범위)에 복사되므로, 민감하면 `link` 로 두거나 넣지 않는다.
- 형제 경로 확인(③)은 보수적이다(`../` 토큰이 보이면 원래 작업 트리로). 흔한 `cd ..` 같은 것도 걸려 작업 트리가 안 될 수 있으나, 안전한 쪽(원래 작업 트리 + 알림)으로 떨어지므로 막지 않는다.
- config include 가 쓰기 범위 안을 가리키면 출발 거부(뒤집을 수 있음: `.git` 안을 가리키는 흔한 include 도 거부될 수 있어, 그럴 땐 밖으로 옮기거나 `worktree_mode` 를 쓴다).
- `gitDirOK` 는 엔진의 쓰는 git(switch·병합·ref 올리기) 앞에만 건다(읽기 git 까지 다 바꾸지 않는다). `.git` 바꿔치기는 샌드박스가 이미 막으므로 받침이다.
- `prerun` 은 따로 작업 트리면 임시 분리 작업 트리에서 돈다(명령 글은 바꾸지 않고 cwd 만 — 판정이 절대 원래 경로를 가리키면 그 부분은 맞지 않을 수 있다, 한계).

### 남은 한계

- ④ precheck 실패 fallback 은 코드로 두고 실제 실패 사례로는 재지 않았다(precheck 가 작업 트리에서 통과하는 흐름만 장난감에 있었다).
- 작업 트리 모드에서도 claude 가 원래 저장소 맨 위에 빈 `.cc-writes` 를 만들 수 있다는 옛 기록(2026-10-21)은 이 실측에서 재현되지 않았다(원래 저장소가 쓰기 범위 밖이라 생기지 않았다). 작업 트리 쪽 `.cc-writes` 만 끝에 치운다.
- `prerun` 작업 트리는 판정 명령 글의 절대 경로를 바꾸지 않는다(cwd 만). 판정이 상대 경로를 쓰면 맞고, 절대 원래 경로를 쓰면 다를 수 있다.
- 묶음(저장소 둘 이상)의 따로 작업 트리는 여전히 9단계로 미룸(지금은 원래 작업 트리 + 알림).
- `finish merge` 뒤 작업 트리를 지우므로, dev 에 합친 뒤 live 승격은 가지 ref 로만 한다(작업 트리 없이). 커밋 안 한 변경이 남은 작업 트리는 지우지 않고 알린다(사람이 본다). Jira 실행에서 `merge --story` 로 한 스토리를 합치면 공유 작업 트리를 지우므로, 아직 안 합친 다른 스토리의 체크아웃을 작업 트리에서 보려면 그 가지를 따로 체크아웃해야 한다(일은 가지에 커밋되어 있어 잃지 않는다).
- 작업 트리 모드에서 모델이 새로 만든 가지를 `created: by: other` 로 보고하는 것은 원래 작업 트리 모드(2차)에서만 확인했고 작업 트리 모드 엔진 실행으로는 재지 않았다(코드 경로는 같다).

정리: `~/workspace/zz-autopilot-wt-measure/`(실측), `~/workspace/zz-fix3-toys/`(장난감), `~/.claude-board/worktrees/zz-fix3-*` 와 `.prerun-*`, 시험 빌드 뿌리의 `zz-fix3-*` 실행 폴더·엔진 전용 폴더·프로젝트 설정, 기록 저장소의 그 행, 시험 세션 기록을 지웠다. LaunchAgent·남은 엔진 0.

비용: 시험 모델 비용 합 약 0.10 USD(haiku 엔진 실행과 쓰기 범위 실측. 가짜 claude 의 값은 실제 비용 아님).

- 장난감 저장소는 세션 scratchpad 에 만든다(저장소 안에 만들지 않음). 실행 폴더는 scratchpad 나 실제 자리(`~/.claude/notifier/autopilot/runs/zz-…`, 보호 경로 동작까지 보려면 이쪽 — 끝나면 지운다). 실행 폴더 이름이 실행 id(영문·숫자·`.-_`). 최소 `run.json`: `{"model": "haiku"}`(사용자 settings 는 엔진이 늘 뺀다), `queue.json`: `[{"title": "…", "prompt": "…", "check": "test -f done.txt", "cwd": "<저장소 절대 경로>", "caps": {"minutes": 2, "usd": 1}}]`. 출발 전 `<엔진> status <실행 폴더>` 로 확인 결과를 본다.
- scratchpad 는 Claude 의 임시 폴더 아래라 샌드박스가 늘 쓰기를 허용한다 — "범위 밖 쓰기" 시험은 `~` 같은 곳으로 한다.
- 보기: `<실행 폴더>/pinned/claude-autopilot status <실행 폴더>`, `engine.log`, `events.jsonl`, `units/<n>/engine.json`·`stream.jsonl`. 조작: `control <실행 폴더> pause|resume|stop`, 강제 종료는 `run.json` 의 `engine_pid` 에 `kill -9`.
- 한도 흐름: `run.json` 에 `"claude_path": "<저장소>/docs/자율주행/시험 도구/가짜 claude.py"`, 단위 `caps.weekly_pp` 를 100 으로(가짜의 주간 1.0 때문에). 대기는 약 3분.
- 확인 스크립트에서 `ps`·`pgrep -f` 로 명령 글자를 찾으면 그 확인 명령을 돌리는 zsh 자신도 걸린다(모델도 같은 착각을 했다) — `zsh -c` 줄은 빼고 본다.
- 자율주행 세트를 시험하려면 `run.json` 에 `"project": "<시험 이름>"` 을 넣고 시험 빌드 뿌리 `~/Library/Application Support/Claude Board Dev/autopilot/private/projects/<시험 이름>/set/autopilot.md` 에 지시를 둔다. 출발 전 확인은 `status <실행 폴더> --dev`(세트를 시험 빌드 뿌리에서 찾음).
- 기록 저장소는 `sqlite3 "file:<뿌리>/autopilot/private/records.sqlite?mode=ro"` 로 읽는다. 옮겨 담기 시험은 `records import --db <scratchpad 파일> …` 로 사본 저장소에 한다.
- 시험 단위에 기다리기가 필요하면 `sleep N` 대신 `python3 -c 'import time; time.sleep(N)'`(Claude Code 가 Bash 의 `sleep 40` 을 막는다, 엔진 고침 1차 실측).
- 가지(엔진 고침 2차): 장난감 저장소에 main·dev·live·master 를 두고 `run.json` 에 `"base_branch": "live"`(지금 가지와 다른 머리에서 시작하는지 보려면 live 에만 커밋 하나). 끝난 뒤 `<엔진> finish <실행 폴더> merge --into dev`·`promote live --into master`·`discard`(Jira 실행은 `--story <키>`). 승격 차례는 시험 빌드 뿌리 `projects/<시험 이름>.json` 의 `promotion`, Jira 꼴은 같은 파일의 `tickets.branch_names`·`merge`. 단위에 `story`·`tickets`(작업 키 하나)·`depends` 를 넣으면 Jira 흐름. 받는 가지에 사람 커밋을 체크아웃 없이 넣으려면 임시 색인(`GIT_INDEX_FILE`)으로 `read-tree` → `hash-object -w` → `update-index --cacheinfo` → `write-tree` → `commit-tree` → `update-ref`.
- 판정 미리 돌리기: 출발 전에 `<엔진> prerun <실행 폴더> --dev`, 결과는 `prerun.json` 과 `prerun/<n>/`(출발 전 `status` 에 한 줄).
- 따로 작업 트리(3-2): 장난감 단일 저장소는 **tmp 밖**(`~/workspace/…`)에 둔다 — scratchpad 는 샌드박스 기본 쓰기 허용이라 "원래 작업 트리 못 씀"이 확인되지 않는다. 작업 트리는 `~/.claude-board/worktrees/<실행 id>/<저장소>/`. 다시 돌리기 전에 그 자리(`worktree prune` + `rm -rf ~/.claude-board/worktrees/<실행 id>`)를 치운다(남아 있으면 `start` 가 "작업 트리 자리가 이미 있습니다"로 거부 — 안전장치). 엔진 샌드박스 안 보호는 단위 prompt 가 자기 자리를 알아내 공격을 시도하는 probe 를 한 번 돌려(hooks·`switch dev`·다른 가지·replace·shallow·`.git` 파일·commondir) `probe-out.txt` 로 확인한다. 모드 결정은 `status` 만으로(저장소 묶음·submodule·`../` 형제 경로·`worktree_mode` 강제·config include). 쓰기 범위를 Claude Code 샌드박스로 따로 잴 때는 작업 트리를 `git worktree add -b` 로 만들고 allowWrite=작업 트리, denyWrite= 다른 가지 ref·`.lock`·HEAD·packed-refs·config·공통 `.git` 설정 자리·replace·shallow·작업 트리 `.git`·commondir·gitdir.
- 쓰기 범위를 Claude Code 샌드박스로 따로 잴 때: `claude -p --settings <샌드박스 설정> --setting-sources project,local --permission-mode dontAsk --permission-prompts none --strict-mcp-config --allowedTools … --disallowedTools …` 에 질문은 표준 입력으로(`--disallowedTools` 가 뒤 글을 삼킨다), 결과 폴더는 절대 경로로(claude 의 작업 폴더 기준으로 읽는다). 장난감은 tmp 밖에도 하나 둬서 대조한다(2차 실측에서 두 자리 결과가 같았다).
- 끝나면: `launchctl list | grep autopilot` 과 `~/Library/LaunchAgents/*autopilot*` 가 비었는지, 시험 세션 기록 `~/.claude/projects/<scratchpad 경로>/` 를 지운다(이번 시험분은 지움).
